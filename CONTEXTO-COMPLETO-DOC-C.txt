4. ARCHIVOS DEL PROYECTO Y QUE HACE CADA UNO
================================================================================

main.py
  - Webhook Chatwoot: recibe mensajes, debounce 30s, processing lock
  - Flujo principal: check IA pausada → check handoff → detectar fecha/hora
    → obtener slots → Claude genera respuesta → crear cita si [CITA_JSON]
    → handoff si [SUPERVISOR] → enviar respuesta → registrar ejecución
  - APIs: citas CRUD, auth JWT, GCal, días bloqueados, handoff, usuarios
  - Background: _followup_loop cada 15 min (seguimientos)
  - AI_ENABLED = os.getenv("AI_ENABLED", "false") — default APAGADA

ai_engine.py
  - SYSTEM_PROMPT: personalidad del agente, reglas, flujo de conversación
  - generate_response(): llama Claude API con contexto (fecha Lima, slots, historial)
  - extract_appointment_json(): detecta [CITA_JSON]{...}[/CITA_JSON] en respuesta
  - extract_supervisor_tag(): detecta [SUPERVISOR]motivo[/SUPERVISOR]
  - clean_response(): limpia tags internos, convierte **bold** → *bold* para WA
  - get_followup_message(): mensajes de seguimiento aleatorios

appointments.py
  - init_db(): crea tablas (citas, ejecuciones, seguimientos, gcal_tokens, dias_bloqueados)
  - crear_cita(): INSERT con anti-duplicado por conversation_id
  - generar_slots(): genera horarios cada 10 min, excluye receso 1-2pm
  - get_slots_disponibles(): filtra por ocupados + GCal busy + días bloqueados
  - Seguimientos: upsert, pendientes (solo interesados), cerrar, expirar
  - Días bloqueados: bloquear/desbloquear/listar
  - GCal tokens: save/get/delete

conversation.py
  - Estado en Redis con TTL 1h
  - get_state / save_state / delete_state / add_message
  - Key: docc:conv:{conversation_id}

models.py
  - ConversationState: contact info, step, fecha/hora elegida, messages[],
    cita_creada (bool), handoff (bool)
  - Cita: nombre, telefono, fecha, hora, motivo, canal, estado, conversation_id
  - EstadoCita: pendiente, confirmada, cancelada, no_contesto, atendida
  - Canal: whatsapp, instagram, messenger, tiktok, web

config.py
  - Variables centralizadas desde env vars
  - Horarios: 8:30-16:00 (L-V), 8:30-12:00 (Sab), Dom NO
  - Receso: 1pm-2pm
  - INTERVALO_CITAS_MIN=10, SLOTS_VISIBLES=3, AI_MAX_TOKENS=250

chatwoot_client.py
  - send_message(): envía mensaje a conversación (outgoing o private)
  - add_label(): agrega label (cita_agendada, supervisor)
  - assign_team(): asigna conversación a team
  - toggle_status(): cambia status (open, resolved, etc)

transcriber.py
  - transcribe_audio(): Whisper para audios de WA
  - describe_image(): GPT-4o Vision para imágenes

gcal.py
  - Google Calendar: OAuth2, crear/editar/eliminar eventos, colores por estado

auth.py
  - JWT, bcrypt, usuarios, Google OAuth auto-creation

static/dashboard.html — Panel web completo (login + calendario + agenda)
static/login.html — Página de login


5. FLUJO COMPLETO DEL AGENTE
================================================================================

PASO 1: Paciente escribe por WA/IG/TikTok
  ↓
PASO 2: Chatwoot recibe → webhook POST a /webhook/chatwoot
  ↓
PASO 3: Si AI_ENABLED=false → ignorar
  ↓
PASO 4: Debounce 30s (acumula mensajes rápidos del mismo paciente)
  ↓
PASO 5: Processing lock (evita procesar misma conversación en paralelo)
  ↓
PASO 6: Check Redis: ¿handoff activo? → SI: IA no responde, sale
  ↓
PASO 7: Detectar fecha/hora en el texto del paciente
  ↓
PASO 8: Si hay fecha → obtener slots disponibles:
         - Generar todos los slots del día (cada 10 min)
         - Excluir receso 1-2pm
         - Excluir slots ocupados (citas en BD)
         - Excluir slots de GCal
         - Verificar si día está bloqueado → 0 slots
         - Mostrar solo 3 slots dispersos (SLOTS_VISIBLES)
  ↓
PASO 9: Claude genera respuesta con contexto:
         - Fecha actual en español (Lima timezone)
         - "Mañana es [día]" (evitar confusión)
         - Nombre/teléfono del contacto
         - Slots disponibles para la fecha
         - Historial (últimos 8 mensajes)
         - Si cita_creada: "NO repitas handoff"
  ↓
PASO 10: Analizar respuesta de Claude:
         - ¿Tiene [CITA_JSON]? → Crear cita en BD
           - Anti-duplicado: check conversation_id en BD
           - Auto-handoff: state.handoff=True, state.cita_creada=True
           - Cerrar seguimiento
           - Label "cita_agendada" en Chatwoot
         - ¿Tiene [SUPERVISOR]? → Handoff a supervisor
           - state.handoff=True
           - Cerrar seguimiento
           - Label "supervisor" + nota privada al equipo
  ↓
PASO 11: Limpiar respuesta (quitar tags, **bold** → *bold*)
  ↓
PASO 12: Enviar respuesta al paciente via Chatwoot
  ↓
PASO 13: Registrar en BD (ejecuciones) + tracking seguimiento


6. SISTEMA DE HANDOFF (SUPERVISOR)
================================================================================

Tres formas de activar handoff:

A) AUTOMATICO (post-cita):
   - IA crea cita → handoff=true → IA deja de responder
   - Equipo ve la cita en dashboard, llama y confirma
   - Label "cita_agendada" en Chatwoot

B) IA DECIDE ([SUPERVISOR]):
   - Paciente pide hablar con humano, se queja, preguntas médicas complejas
   - IA incluye [SUPERVISOR]motivo[/SUPERVISOR] al final
   - handoff=true, nota privada al equipo en Chatwoot
   - Label "supervisor"

C) MANUAL (API):
   - POST /api/conversations/{id}/handoff {"activate": true}
   - Para casos donde el equipo quiere tomar control manualmente

Desactivar handoff (devolver a IA):
   - POST /api/conversations/{id}/handoff {"activate": false}

Consultar estado:
   - GET /api/conversations/{id}/handoff


7. SISTEMA DE SEGUIMIENTOS
================================================================================

Mensajes de follow-up automáticos para pacientes que no respondieron.

Reglas actuales (v24):
- Solo 1 seguimiento (no 2)
- Solo si el paciente mostró INTERÉS (mencionó cita, consulta, horario, etc)
- Se envía 2 horas después del último mensaje sin respuesta
- Dentro de ventana 24h de Meta
- NO se envía a: pacientes con cita, en handoff, o pasados a supervisor
- NO se envía fuera de horario (9pm-8am Lima)
- Background loop cada 15 minutos

Safety net: antes de enviar, verifica en Redis si hay handoff/cita_creada.
Si encuentra alguno, cierra el seguimiento en BD y no envía.

12. PROTECCIONES Y SAFETY NETS
================================================================================

- AI_ENABLED default false: cada deploy arranca con IA apagada
- Debounce 30s: acumula mensajes rápidos, no responde a cada uno
- Processing lock: una conversación no se procesa en paralelo
- Handoff check: si handoff activo, IA no responde
- Anti-duplicado citas: Redis (cita_creada flag) + PostgreSQL (conversation_id)
- Timezone Lima: todas las fechas usan America/Lima (servidor en UTC)
- Fechas en español: "lunes 26 de mayo" (no "Monday May 26")
- Receso 1-2pm: no genera slots en ese rango
- Días bloqueados: equipo puede bloquear días llenos
- Seguimientos controlados: solo 1, solo si hubo interés, no a handoff/cita
- WhatsApp markdown: auto-convierte **bold** a *bold*
- max_tokens 250: respuestas cortas obligatorias


13. BUGS RESUELTOS (HISTORIAL)
================================================================================

- IA respondía con IA pausada: AI_ENABLED se reseteaba a true en deploy.
  Fix: default "false" desde env var.

- Fechas incorrectas (UTC vs Lima): servidor en UTC, Lima es UTC-5.
  Fix: todo usa ZoneInfo("America/Lima").

- Días en inglés ("Monday"): strftime daba inglés.
  Fix: arrays manuales dias_es[], meses_es[].

- IA repetía "¿Cuál es su motivo?": no leía historial.
  Fix: regla anti-repetición en prompt + historial como contexto.

- Citas duplicadas (3 para mismo paciente): flag Redis no bastaba.
  Fix: check PostgreSQL por conversation_id antes de INSERT.

- Follow-ups a pacientes con cita/supervisor: no verificaba handoff.
  Fix: cerrar seguimiento en handoff + safety net en loop.

- DNI vacío colisionaba (dashboard médica): "" conflicto UNIQUE.
  Fix: migration_v16 (DROP NOT NULL + partial unique index).
